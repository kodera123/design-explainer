# 構成の案の書き方

図も本文も作る前に、次の5つを1つのメッセージで出す。返事がほしいことは最後に並べる。

1. **目的の読み取り**（1文）：「開発チームが5分で読んで、〜の設計に大きな抜けがないかを判断できる」
2. **最後まで使う例**（3つ。日付と金額まで決める）
3. **節と図**（表。節、図の中身、文の量）。表の下に、字数の見積もりを1行で添える（図の枚数 × 300 ＋ 本文。5分なら約2,500字まで）
4. **聞きたいこと**：図が描けなくなる点だけ。残りは「未決定としてページに載せる候補」として並べる
5. **未確認のこと**：まだ読んでいないコードやページ

置き場所は、この案と一緒に聞いてよい。

## 返事の読み方

| 返ってきたもの | 扱い |
|---|---|
| 「これで作って」「進めて」「いいね、それで」「よろしく」など、進める言葉がある | 了承。細部の訂正が付いていれば、反映して作り始める。置き場所が未回答なら、載せる前までに聞く |
| 置き場所や細部への答えだけで、進める言葉がない | 了承ではない。「構成はこのままで作ってよいですか」と1文で確かめる |
| 構成への直し | 直す内容がそのまま指定されていれば（例は2つにして、など）、反映して作り始め、変えた所を伝える。型の決まりよりユーザーの指定を優先する。方向だけの指摘なら、変わった所だけを示してもう一度確かめる。案を全部は出し直さない |
| どの問いへの答えか分からない | 読み取った意味を1文で言い、構成を確かめる |

- 了承を待つ間にしてよいのは、読む作業だけ（コード、元の設計ページ、置き場所のページ、figkit の見本）。図、本文、Notion のページは作らない。
- 途中で気づいたあいまいな点も、最初と同じに扱う。図が描けなくなるものだけを聞き、残りは未決定としてページに載せる。

## 見本（検証用サーバーの月額費用を、月ごとに残す設計）

題材は架空のもの。社内の管理ツールで検証用サーバーを貸し出していて、今は過去の月の費用が出せない、という設定にしている。`scripts/example_figures.py` の図も同じ題材で描いている。

目的：開発チームが5分で読んで、月ごとの費用を残す設計に大きな抜けがないかを判断できる。

例：

| | 出来事 | 確かめられること |
|---|---|---|
| web-1 | 11/10 に作って、そのまま使い続ける | 作った月の扱い（日割りしない） |
| db-1 | 12/15 にサイズを S から L に上げる | 月の途中の変更が、月末のサイズで数えられること |
| batch-1 | 1/20 に削除する | 月の途中で消したサーバーが、どの月まで数えられるか |

節と図：

| 節 | 図の中身 | 文 |
|---|---|---|
| 何を作るか | なし | 3〜4文 |
| 今、サーバーのデータはどう残っているか | 3台 × サーバーのテーブルと操作の履歴に残るレコード | 1文 |
| 毎晩のバッチが行を作る | 1回の実行ですることを3段で。段ごとに見るテーブル | 1文 |
| 残るレコード | 行の例（基準の行と、違う所に色）。カラムと使い道 | 持たせていないものを箇条書き |
| 3つの例で、費用は想定どおりになるか | 3台 × 4か月の行、合計、前の月との差 | 1〜2文 |
| 変更が起きたとき | 停止、料金の改定、後から登録された削除 | なし |
| 集計での動き | テーブルから、ビュー、ダッシュボードまで | 2文 |
| 見てほしい点 | Notion の表（決めたこと・その結果）4行 | なし |
| 参考 | 折りたたみ。カラムの出どころ、金額の決め方、細かい決まり | 字数に入れない |

字数の見積もり：図6枚 × 300 で約1,800字、本文は約700字、合わせて約2,500字（参考は数えない）。

聞きたいこと：月の途中で作ったサーバーと消したサーバーは、日割りしない（月末にあれば1か月分、なければ0）でよいか。答えで、3つの例の金額が変わる。

未決定としてページに載せる候補（要らなければ削ってほしい）：
- 4か月以上前の削除が後から登録されたときの直し方。見直しの範囲の外なので、合計に残ったままになる

未確認のこと：ダッシュボードが今どのテーブルを読んでいるか。料金表の改定の履歴が、どこかに残っているか。

返事がほしいこと：この構成で作ってよいか。日割りしないでよいか。ページの置き場所。
