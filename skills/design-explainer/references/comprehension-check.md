# 別のエージェントに、読めるかを確かめさせる

「分からない言葉を挙げて」と頼むだけでは、読み手が中身を理解できたかは分からない。1回だけ読ませて、見返さずに問いに答えさせる。

## 準備

- 本文を markdown のファイルに書く。図の位置は `[図 名前：題]` と書く。
- 問いを 8〜10 個作る。ページの目的から逆に作る：「なぜこれが要るのか」「1行は何を表すか」「2つ目の例はどうなるか」「例外が起きたら何が起きるか」「どこで計算するか」「設計上の注意点を2つ」。答えが図か本文に1か所だけあるものにする。
- `python3 scripts/figkit.py count` で字数を出しておく。

## 頼み方

新しいエージェント（general-purpose）に、次だけを渡す。この会話の経緯、過去の指摘、設計の背景は渡さない。

```
あなたは〈読み手の立場。例：EC サイトの会社のバックエンド開発者〉です。〈一般知識として持つもの〉は分かりますが、
このプロジェクトの経緯や設計は何も知りません。同僚から「5分で読めるので、設計に大きな抜けがないか見てほしい」と
ページを渡されました。

読むもの（この順に、上から1回だけ読む。読み返さない）：
- 本文：〈markdown の絶対パス〉
- 本文の [図 …] の位置に入る図（Read で見る）：〈PNG の絶対パスを順に〉
ほかのファイル、コード、Web は見ないでください。ファイルは書き換えないでください。

読み終えたら、資料を見返さずに、次の順で報告してください。
【1】理解の確認（覚えている内容だけで答える。分からなければ「分からない」と書く）
 Q1. …  〜 Q9. …
【2】5分で読めるか：体感で読めたか（はい／いいえ、理由1文）。立ち止まった所（最大5個）。削っても困らない所（最大5個）
【3】設計について聞きたくなった疑問（最大5個）。図と本文、図どうしの食い違い（見つけたものすべて）
【4】意味が取れなかった言葉・不自然な日本語（最大5個）
各項目は1〜2文で具体的に。
```

## 結果の使い方

- **問いの答えを自分で採点する。** 外れた問いは、その内容が図か本文から読み取れていない。
- **立ち止まった所と食い違いは直す。** 「削っても困らない所」は、ユーザーが残すと言った内容なら残す。
- **設計への疑問は、ページに足さずにユーザーへ報告する。** レビューで実際に聞かれる点で、設計の抜けが混ざっていることがある。
- **エージェントは時間を計れない。** 「3〜4分で読めた」は体感の申告として報告し、字数の見積もりと並べる。
- **図は1枚ずつ「3秒でどこを見ればよいか分かったか」も聞ける。** 節だけを作り直したときに使う。
- 直した後の版は、もう一度読ませるか、「直した後は読ませていない」と報告に書く。
